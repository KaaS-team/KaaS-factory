## Issues

### #580 Create and merge PRs over REST with timeouts

## Problem

The `gh` CLI can hang with no output, which stalls PR create and merge in the runner and in hand work.

## Acceptance

- PR create and merge use the REST API with a request timeout.
- A timed-out call fails the step with the call named, and is retried once.
- A test with a stalled server proves the timeout fires.

## Out of scope

- Other `gh` uses.

### #584 Verify SHA256SUMS in the release workflow

## Problem

The release workflow publishes binaries and a checksum file, but nothing proves the checksums match the files before the release is published.

## Acceptance

- The workflow recomputes each checksum and fails the release when one differs.
- A test with a corrupted file proves the failure.

## Out of scope

- Signing releases.

### #586 Delete merged feat branches

## Problem

Merged `feat/*` branches stay on the remote. Fourteen were found at the last probe, and they hide the branches that matter.

## Acceptance

- A merged `feat/*` branch is deleted after its PR merges.
- Existing merged branches are removed once.
- A test proves an unmerged branch is never deleted.

## Out of scope

- Branches of open PRs.

### #583 Do not rerun checks when only the PR body is edited

## Problem

Editing a PR description reruns the checks that read it, so a typo fix starts a full run and can cancel a green one.

## Acceptance

- A body edit reruns only the check that reads the body.
- A test or workflow assertion proves other checks are not triggered by a body edit.

## Out of scope

- Changing what the body check requires.

### #567 A cancelled ci run is not restarted, and docker-egress-network flakes

## Problem

Two CI failures cost reruns by hand:
1. A cancelled CI run (for example when a newer push supersedes it) is never restarted, so a PR can sit with no result until someone notices.
2. The docker egress network test is flaky and fails runs that touched nothing near it.

## Acceptance

- A PR whose latest CI run was cancelled gets a fresh run, and the merge step never treats a cancelled run as green.
- The docker egress network test passes on ten consecutive runs, or is isolated so it cannot fail an unrelated PR.
- A test covers the cancelled-run case and fails when the restart is removed.

## Out of scope

- Changing which checks are required.

### #348 Every CI check must pass on the current tree before it is wired

## Problem

A CI check can be wired in while it already fails on the current tree. It then blocks every later PR for a cause unrelated to that PR. Three real cases were a semgrep rule, a missing timeout and an out-of-date ledger.

## Acceptance

- A check cannot be added to the required list unless it passes on the current main tree. The change that adds it proves this.
- The semgrep rule that fails on main is fixed, or scoped so it passes.
- A structural test fails when a new check is wired and red.

## Out of scope

- Which checks should exist.
