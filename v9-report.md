## Ticket: unit-economics report

`factory report`: is the factory paying for itself? Tokens per merged PR, rework rate, human touches per PR, cycle time, and cost by workflow and by pack.

Read first: `internal/meter` (ledger, `<!-- factory:spend v1 -->`), `internal/store`, `internal/observe`. Symphony §13.5 for token accounting.

Design to follow:
- `report.Build(ctx, Source, Window) (Report, error)` where `Source` is a narrow interface over the store and the ledger; a fake in tests.
- Definitions, written once in `definitions.go` and used everywhere: merged PR = a ticket whose PR merged in the window; tokens per merged PR = all tokens spent on tickets merged in the window, including failed attempts, divided by merged PRs; rework = attempts above one; human touch = any `/factory` chatops command or manual push on the ticket branch; cycle time = first dispatch to merge.
- Output as markdown and JSON. `report.NewCommand()` for `factory report [--since 7d] [--json] [--by team|workflow|pack]`.
- Operator-only: the command refuses to write into a path under `.github/` or a PR body file.

## Acceptance

- [ ] Each definition has a table test with a hand-computed fixture row.
- [ ] Failed attempts count toward tokens per merged PR; a ticket that never merged adds to spend but not to merged PRs.
- [ ] `--by team` groups correctly over a fixture with two teams (golden).
- [ ] JSON and markdown agree on every number (test computes both and compares).

## Order of work

For each acceptance line: write the test, watch it fail, write the code, watch it pass. Port behaviour from the TS file named in the ticket and keep its wire formats byte for byte (markers, comment bodies, argv). A file copied from another repo starts with `// Ported from <repo>@<sha> <path>` and only from MIT or Apache-2.0 code; add its `## <repo>@<sha>` section to `THIRD_PARTY_NOTICES.md` (the provenance test fails otherwise).

Commit with `git commit -s`, one commit per acceptance group, and push after each: `git push -u origin go/report`. Run `just fast` before every push and `just check` before the last one.

## Checkpoints, before every commit

1. Area: every changed file is in your area or listed under "Files outside my area".
2. Scope: the diff serves only an acceptance line below. No refactor of other packages, no extra feature.
3. Meaning: each acceptance line still means what it says. If it cannot be met, record it blocked; never weaken it.
4. Proof: you saw each new test fail before the code and pass after.
5. No network, real token or model call in any test. Fakes from `internal/api/porttest` or a local `httptest.Server` only.
