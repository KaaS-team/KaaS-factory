Every ticket type runs its own workflow

The loop is the same for every ticket: triage, plan, build, verify, review, deliver. What changes per type is the trigger, who triages, the risk tier, which steps are plain scripts, where the human sits, when it stops, and what you measure. These are starting defaults drawn from how Anthropic, Stripe, Spotify, Uber, Google SRE, CISA and GitHub run them. Copy one into a Workflow card and change it to fit your team.

AFour rules every workflow below follows

  1. Scripts where you can, agents where you must. Stripe's Minions mix fixed steps (lint, push, run CI) with agent steps (write the fix). Anything with one right answer is a script.
  2. The change sets the risk tier. Paths, size and data touched decide who approves, never who or what wrote it. An agent's approval never counts as a person's.
  3. Every loop has a cap. Stripe allows two CI rounds per run. Anthropic caps agent review at three rounds after one PR went through fifty overnight. When the cap is hit, a person gets the issue with the reason.
  4. Fix a repeated finding at the source. The third time a reviewer says the same thing, it becomes a rule, a skill, a lint or a test.

CThe workflows

Small bug Low to medium

Trigger
Issue with steps to reproduce, labelled ready.
Path
triage → failing test → fix → gates → verify (revert, test fails) → PR
Scripts
Gates, the revert proof, the PR template.
Agent
Reproduces, writes the failing test, makes the smallest fix.
Human
Reviews the PR. Low tier when only covered, non-sensitive files changed.
Stops when
No failing test after one try: ask the reporter. Two rejected builds: park for a person.
Watch
Reopen rate; time from ready to PR.

Unclear bug or support report Needs info

Trigger
Support inbox, a customer message, a vague issue.
Path
dedupe → ask for what is missing (max 2 rounds) → reproduce → becomes a Small bug, or closes with a reason
Agent
Searches past issues and logs, drafts the question, attaches what it found.
Human
Support or the owner answers. Only trusted accounts can steer the agent.
Stops when
Two question rounds with no answer: close as cannot reproduce.
Watch
Share of reports that reach a reproduction.

Dependency update (Dependabot, Renovate) Low for patch and minor

Trigger
Weekly schedule. Security updates skip the schedule.
Path
group patch + minor into one PR → wait until the release is 3 to 7 days old → CI → auto-merge
Scripts
All of the happy path. No agent at all when CI is green.
Agent
Only when CI breaks or for a major: reads the changelog, fixes breaking calls, summarises risk in the PR.
Human
Every major version, one PR each. Auto-merge only in repos with real test coverage.
Stops when
Fix needs more than the files that call the package: park, it is a migration.
Watch
Open update PRs; days behind latest.

Security finding in a dependency (CVE alert) High

Trigger
Dependabot or scanner alert.
Path
enrich (CISA KEV, EPSS, reachable?, exposed?) → decide with SSVC (Track, Track*, Attend, Act) → patch or mitigate → regression test → PR
Scripts
KEV and EPSS lookup, the SLA clock, the upgrade itself.
Agent
Proves whether our code reaches the vulnerable function and writes that up as evidence.
Human
Security owner decides the outcome. Never auto-merged.
Stops when
SLA tier: exploited in the wild within days (the KEV catalog sets a due date for US federal teams), the rest in weeks.
Watch
Time to remediate by tier; alerts past SLA.

Security bug in your own code High

Trigger
Private report, bug bounty, pen test. Never a public issue.
Path
private advisory → reproduce in an isolated worktree, no network → fix + regression test → hunt the same bug class elsewhere → two reviewers → coordinated release
Agent
Writes the exploit as a failing test, then searches for variants of the same pattern.
Human
Two people, one of them the security owner. Disclosure timing is a person's call.
Watch
Variants found per report: the real payoff of the agent here.

Incident People lead

Trigger
Alert or customer impact. Declare early, downgrade freely.
Path
declare + severity → incident commander → mitigate (roll back, flag off) → resolve → blameless postmortem → action items become issues
Agent
Scribe and investigator: keeps the timeline, diffs what shipped since the last good deploy, searches logs and traces, drafts the status update and the postmortem.
Human
The commander decides every action on production. Mitigate first, fix later.
After
Each action item runs as a Small bug or Feature. The incident becomes an eval case for your reviewer.
Watch
Time to mitigate; action items closed.

Flaky test Medium

Trigger
A test that fails then passes on retry. Google found most pass-to-fail changes after submit involved a flaky test.
Path
detect → quarantine with an owner and an expiry (30 days) → agent finds the cause → fix → back in the gate
Human
Approves any change that deletes or weakens a test.
Watch
Quarantined tests past expiry; flake rate.

Feature from product Medium

Trigger
A shaped pitch: problem, appetite (how much time it is worth), rough solution, rabbit holes, no-gos.
Path
spec (requirements → design → tasks) → human approves the spec → each task runs build-verify-PR → feature flag → staged release
Agent
Drafts the spec from the pitch and the code, lists open questions, writes tasks with acceptance criteria.
Human
Approves the spec before any code. Product checks it behind the flag.
Watch
Spec rework rounds; scope added after approval.

Epic into tasks Medium

Rule
Cut vertical slices, each shippable on its own behind a flag and small enough to review in about fifteen minutes.
Path
epic → slices → dependency order → tasks that touch different files run in parallel → one PR per task
Human
Approves the slice list and the order. Each PR follows its own tier.
Watch
PR size; tasks blocked on another task.

Refactor or migration across many repos Medium

Path
codemod for the common case → agent for the long tail → one PR per repo → existing CI verifies
Evidence
Spotify's Honk opened hundreds of migration PRs. It did well on standard frameworks and struggled on unusual ones, so standardise first.
Watch
Merged versus opened; review time per PR.

Docs or copy Low

Path
triage → build → link and prose checks → PR → merge on green
Human
None for low tier once checks pass. Pricing and legal copy are high tier.
