The factory loop turns a labelled issue into a PR a human merges

A software factory is a runner that takes an issue through triage, plan, build, verify and PR with no one at the keyboard. Each stage is a skill in its own worktree. The runner, not the agent, decides green or red.

Compare it with week one. Param still labels, approves and merges. Everything between those three clicks now has a check.

We ran the factory on kaas-suite first, and it shipped most of what it took

Dogfooding means running our own tool on our own product before anyone else does. On 11 and 12 October the factory ran 35 issues on kaas-suite, the KaaS.team product apps.

35issues run overnight
30shipped
5cancelled by the operator
29verify rejects, against 24 passes

More rejects than passes is the Tester doing its job: most cards needed a second build. One card was uncertain on all four verify rounds. It shipped because a human read it and merged.

Every failure the factory hits becomes an issue against the factory

The factory repo releases through its own gate. Each new check lands with a mutation that must turn its test red. A bug seen while running kaas-suite is filed against the factory, fixed, and released.

Installing it is three commands per repo, after week three's files exist

The template is the set of hooks, stage skills and gate script the factory copies into a repo. factory init detects the stack and writes the config. gates.sh wraps the repo's own make check.

factory install ~/learn/kaaslabs/kaas.team        # template: hooks, stage skills, gates.sh
factory init --repo-dir ~/learn/kaaslabs/kaas.team  # .factory/config.json from the stack
factory watch --repo-dir ~/learn/kaaslabs/kaas.team # poll and drive the loop

Any coding agent can run a stage, but only Claude gets the path guard

A preset tells the runner how to call one agent CLI. Presets exist for Claude, Codex, Gemini, OpenCode, Cursor, Pi and Mastra Code. Only Claude is verified live by us. A different vendor on verify than on build means the Tester does not share the builder's blind spots.

{
  "agents": { "claude": { "preset": "claude" }, "gemini": { "preset": "gemini" } },
  "stages": { "default": "claude", "verify": "gemini" }
}
SafetyClaudeCodex, Gemini, Cursor, Pi, Mastra CodeOpenCode

So Claude builds anything near a protected path. Another vendor may verify, where a read-only flag is enough.

Key terms

Software factory
A runner that takes an issue to a PR through checked stages.
Dogfooding
Running our own tool on our own product first.
Template
The hooks, stage skills and gate script copied into each repo.
Route
The rule that sends a task type to the factory, a human, or both.
Preset
How the runner calls one agent CLI for a stage.
