Homework: englishmaa.com

englishmaa is the most factory-ready repo we have

A Rust server, a web page and an Expo app share one gate. The repo already has what a factory needs most: an AGENTS.md that says where it differs from the house standard, path rules, an impact map so a change runs only the checks it reaches, and CI. What it lacks is a boundary around money and voice.

1Team and codebase

Repository
Param-Harrison/englishmaa: server/ (axum, sqlx, billing webhooks, live session socket), web/ (Vite), mobile/ (Expo, RevenueCat paywall), vendored avatar SDK.
Gates
make check: impact audit, cargo fmt and clippy with warnings as errors, database tests, web build and SEO, biome, vitest, mobile checks, prose, quality, SDK drift. CI runs it on GitHub with Postgres. The pre-push hook queues it on the build box.
Impact map
.claude/repo.json maps every tracked file to the checks it reaches, and check-impact fails when a file is unmapped.
Protected paths today
Only web/src/sdk/* and */package-lock.json. Plans, prices and billing are not protected.

What the gate cannot see: how the tutor sounds, and what the voice costs per engaged minute. Both need a human or a production probe.

7The factory for englishmaa

Isolation
VM mode. Port 3088 is held by e2e (portsHeldByE2E), so one run at a time, or a port per worktree.
Secrets
No OpenRouter, Plunk, RevenueCat or Stripe keys in the stage env. Tests use the dev Postgres with a throwaway database per test.
Metrics
Time to PR, verify rejects per card, reverts, cost per PR.
Demo card
Re-file "send reminders only to browser push services" against its parent commit and run it end to end.
