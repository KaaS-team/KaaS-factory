The factory ships itself, and runs on our product

Two loops. The factory repo releases through its own gate, and every bug it hits while running real work becomes an issue against itself. The real work was kaas-suite, the KaaS.team product apps: 35 issues run overnight on 11 and 12 October.

3What the retro stage learned

Verbatim lessons from the retros table. Each one is a candidate for a rule or a stage skill edit.

  • #2 "A plan that fans out one LLM call or subprocess per input unit should cap the unit count and total wall-clock runtime up front, and name an env allow-list for any spawned process instead of inheriting the server env."
  • #10 "Never hold a DB transaction or row lock across external I/O such as LLM calls or PR/API calls."
  • #10 "A test-that-bites proof must show a behavioural failure: reverting the change and seeing only compile or missing-module errors proves the file exists, not that the assertions catch a wrong result."

The third lesson is the one to carry into all three apps: a revert that only breaks the import is not proof. Verify must mutate the logic.
