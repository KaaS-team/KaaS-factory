Assignment 1: before any factory

Map how we ship each task type by hand, before any factory

This page maps how we run kaas.team, lwp-academy and englishmaa today, with no factory. Each task type gets one drawing. The drawing shows who does each step, what checks it, and where a check is missing. Every step points at a real commit, PR or alert from October 2026.

Planning lives in specs and Linear, but no commit points back to them

Planning is deciding what to build and in what order. Ours starts as a spec in internal-apps/plan/specs, numbered from 00-ladder to 09. Linear holds one project per product under the team key LEA. The code never names either.

What it costs STATUS.md still says 02-email-plunk is not started. Plunk mail shipped in all three apps on 14 and 15 October. The plan and the code drifted within a week.

Evidence: internal-apps/plan/specs/STATUS.md line 8; zero LEA keys in 60 days of commits across the three repos.

Triage happens in one head, so nothing records what was dropped

Triage is deciding whether a report is real, how urgent it is and who takes it. We have no issues in any of the three repos. A report arrives, Param decides on the spot, and the decision leaves no trace.

What it costs A factory starts from an issue. With no issue, there is nothing to pick up, and no way to count what we dropped.

A small bug gets fixed once per repo, by hand, on the same day

A small bug is a wrong behaviour one change can fix and one test can pin. On 15 October a book download subscribed readers to the newsletter. The same Plunk rule lived in three repos, so the fix was made three times.

What it costs The second and third fixes depend on Param remembering. The support address changed in two repos the same day for the same reason (6516b62, 1d3f1ab).

A Dependabot PR passes CI and then waits, because nobody is told

A Dependabot fix is a version bump that GitHub opens as a PR. Only englishmaa has Dependabot on. Its first PR bumps vite from 8.3.0 to 8.3.4 in /web.

What it costs The fix exists and is proven, yet the open vite alerts stay open until a person clicks merge.

A vulnerability alert gets one decision, and the reason stays in a dropdown

Vulnerability handling is reading a security alert on a dependency and choosing to fix it, accept it or dismiss it. englishmaa has nine alerts so far. Six vite alerts are open today, two of them high.

What it costs The judgement is sound, but it lives in one person's head. A second person, or an agent, cannot tell a reasoned dismissal from a rushed one.

A security bug is fixed when someone spots it, and no test keeps it fixed

A security bug is a flaw in our own code that lets the wrong thing run or the wrong person in. Both examples below were found while doing other work, and both were one-line fixes.

Security checks run in one repo's browser gate and nowhere else

A security check is a script that fails the build when a known class of mistake appears. We have one. lwp-academy's browser gate keeps analytics and Google One Tap off auth pages, whose URLs carry tokens (94505bc).

What it costs Every other security finding depends on a person reading code at the right moment.

Lighthouse is a real gate in two repos, and missing in the third

A Lighthouse check scores a page for performance, accessibility, best practices and SEO. kaas.team and lwp-academy fail the gate below 100 in any category. Mobile Performance is the exception: the median of three runs must reach 95.

What it costs The rule took two commits to make honest. One bad run used to fail the push. One crash used to look like a low score.

A UI change is judged on the live site, so taste reverts reach production

A UI task changes what a reader sees: layout, copy or a component. No script can say whether copy is right. On kaas.team we judge it after deploy, not before.

What it costs The gate checked everything a script can check, and the change was still wrong. The taste check happened on production because there is no preview step.

An epic lands as one long day of commits straight on main

An epic is a change too big for one commit that ships as a planned series. The lwp-academy cutover moved members, auth and Stripe off lwp-website. It landed as 22 commits on 19 October.

What it costs There was no list of the pieces, so done meant "Param stopped". The portal bug was found by clicking the real portal, a day after it went live.

A milestone is a word in a commit message

A milestone is a named group of work with a finish line, such as a store release. englishmaa works in phases. GitHub has zero milestones in all three repos, so a phase exists only where a commit names it.

A revert after a green gate shows what the gate cannot see

A revert undoes a change that already shipped. englishmaa swapped its text to speech fallback to local voices. The gate passed, and the change was undone two hours later.

Review is a click on our own PR, three seconds after opening it

A review is a second reader checking a change before it merges. We have three human PRs in total. lwp-academy PR #2 was opened at 15:18:38 and merged at 15:18:41 by the same account.

Key terms

Manual workflow
A path where a person starts, checks and finishes every step.
Gate
A command that can refuse a change; ours is make check.
Missing check
A step where a mistake would ship because no script looks.
Human in the loop
A step only a person may decide: scope, taste, money or trust.
