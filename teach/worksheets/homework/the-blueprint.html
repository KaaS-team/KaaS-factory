The blueprint

Write the blueprint in the .claude directory, borrowing from five public skill packs

The map of how we work today showed every task type starting and ending in Param's head. The blueprint moves that knowledge into files an agent reads. We compare five public blueprints, map their skills onto our task types, and decide what each of our three repos adopts.

You will learn which blueprint skill covers which of our task types

  • What the .claude directory holds in each of our repos today, and what it should hold.
  • How owainlewis/blueprint, addyosmani/agent-skills, mattpocock/skills, gstack and pstack each walk a change from idea to merge.
  • Which skills we adopt per task type, and how we vendor them so an upstream edit cannot reach a run unread.

Two of our three repos give an agent almost nothing to read

A blueprint is the set of files that tells an agent how this repo works: instructions, rules, skills, hooks and settings. In Claude Code it lives in AGENTS.md or CLAUDE.md and the .claude directory. A factory agent runs in a fresh worktree, so it sees only what the repo holds.

Everything else an agent relies on today comes from Param's home folder and the lwp-claude-plugins enabled on that laptop. A factory run on another machine gets none of it.

owainlewis/blueprint splits define, deliver and check into twelve skills

owainlewis/blueprint is a pack of opt-in skills, installed with npx skills add owainlewis/blueprint. A new project goes requirements, then architecture. A new feature goes spec, then task-to-pr or factory.

addyosmani/agent-skills turns each phase into a checklist with excuses named

addyosmani/agent-skills groups skills by phase: define, plan, build, verify, review and ship. Every skill carries an anti-rationalization table: the excuses an agent gives for skipping a step, each with its rebuttal.

mattpocock/skills keeps each skill small and the human in charge

mattpocock/skills is a set of small skills you compose yourself. It starts by grilling the human until the plan holds, and it ends at a PR. wizard writes a bash script for the steps only a human can do.

gstack runs a sprint from office hours to a canary after deploy

gstack is Garry Tan's MIT skill stack for Claude Code. Its order is think, plan, build, review, test, ship and reflect. It is the only pack here that follows a change past merge, into deploy and a canary.

pstack makes the agent prove a change works before it says done

pstack is poteto's skill stack, mirrored at backnotprop/pstack with ports for Claude Code. Its principles are prove-it-works, fix root causes and encode lessons in structure. /interrogate sends a diff to other models to break it.

We vendor a skill by commit and hash, so an upstream edit waits for a reader

Vendoring copies a skill into our own repo at a pinned version. plugins/lwp-eng/vendor.json in lwp-claude-plugins pins each source to a commit and each file to a sha256. Today it pins addyosmani 1401c8b8, mattpocock 24fe0ef7, obra/superpowers 8ca22dba and trailofbits 82fe8226.

The target blueprint puts the same files in all three repos

Each repo gets the same skeleton, with its own commands and rules inside. The skeleton is what the gates wire into.

AGENTS.md                      commands, the gate, what changes together, what never to touch
CLAUDE.md                      one line: @AGENTS.md
.claude/
  settings.json                deny rules for .env, secrets and deploy config; hooks registered

.githooks/pre-push             make check
.github/dependabot.yml         weekly, grouped minor and patch
.github/workflows/ci.yml       make check on every push and PR
kaas.team needs AGENTS.md, CLAUDE.md, settings.json, repo.json, Dependabot and CI. It keeps its skills and hook.
lwp-academy needs everything: it has no .claude directory, no hook and no CI.
englishmaa needs CLAUDE.md, settings.json, skills and dependabot.yml. Its AGENTS.md, rules and CI stay.

Key terms

Blueprint
The files that tell an agent how this repo works: AGENTS.md, CLAUDE.md and .claude.
Skill
A SKILL.md the agent loads when its description matches the task.
Task route
The skill path one task type follows from start to PR.
Vendoring
Copying a skill into our repo at a pinned commit and hash.
