Before any factory

Map how we ship each task type by hand, before any factory

Before you automate a task, draw how it runs by hand. Start with the one workflow every task follows from triage to merge, then see how each task type bends it.

An oval starts or ends the work. A diamond is a decision. A folded page is a file, and a drum is a branch or a list.

Every task runs one workflow from triage to merge, and skips what it does not need

A workflow is the path a task takes from arriving to going live. Each diamond is a decision, so a task takes only the steps it needs.

The lesson Every diamond is the same person. The workflow is sound, but nothing moves without them.

Planning lives in specs and Linear, but no commit points back to them

Planning is deciding what to build and in what order. Ours lives in spec files and a task board, and the code never links back.

The lesson Our status file still listed email as not started a week after it shipped in all three apps.

Triage happens in one head, so nothing records what was dropped

Triage is deciding whether a report is real, how urgent it is and who takes it. Ours happens in one head and leaves no trace.

The lesson A factory starts from an issue. No issue means nothing to pick up, and no count of what was dropped.

A small bug gets fixed once per repo, by hand

A small bug is wrong behaviour that one change can fix and one test can pin. Ours: a book download subscribed readers to the newsletter, and the same rule lived in three repos.

The lesson The second and third fixes depend on someone remembering.

A Dependabot PR passes CI and then waits, because nobody is told

A Dependabot fix is a version bump that GitHub opens as a PR. Only one of our repos has Dependabot on.

The lesson The fix is proven, yet the alert stays open until a person clicks merge.

A vulnerability alert gets one decision, and the reason is lost

Vulnerability handling is reading a security alert on a dependency and choosing to fix, accept or dismiss it.

The lesson Nobody else, human or agent, can tell a reasoned dismissal from a rushed one.

A security bug is fixed when someone spots it, and no test keeps it fixed

A security bug is a flaw in your own code that lets the wrong thing run or the wrong person in. Both below were found by chance and fixed in one line.

Security checks run in one repo, and nowhere else

A security check is a script that fails the build when a known mistake appears. We have one: trackers stay off pages whose URLs carry login tokens.

What it costs Every other security finding depends on a person reading code at the right moment.

Lighthouse is a real gate in two repos, and missing in the third

A Lighthouse check scores a page for performance, accessibility, best practices and SEO. Two of our repos refuse the push below 100.

The lesson Retry a crash, never a score, or the gate lies in both directions.

A UI change is judged on the live site, so taste reverts reach production

A UI task changes what a reader sees. No script can say whether copy is right, and we judge it only after deploy.

The lesson The gate checked all a script can. Taste needs a preview before production.

An epic lands as one long day of commits on main

An epic is a change too big for one commit. Ours moved members, login and payments to a new app in 22 commits in one day.

The lesson With no list of the pieces, done meant someone stopped.

A milestone is a word in a commit message

A milestone is a named group of work with a finish line, such as a store release. Ours exist only in commit messages.

A revert after a green gate shows what the gate cannot see

A revert undoes a change that already shipped. Ours swapped the voice engine, passed the gate, and was undone two hours later.

Review is a click on our own PR

A review is a second reader checking a change before it merges. Ours took three seconds, by the person who opened it.

Most task types already have a check, but every one starts and ends with a human

A task type is ready for a factory when a script can prove the outcome. It stays human when the outcome is taste, money or trust.

Key terms

Workflow
The path a task takes from the moment it arrives to the moment it is live.
Manual workflow
A workflow where a person starts, checks and finishes every step.
Gate
A command that can refuse a change; ours is make check.
Missing check
A step where a mistake would ship because no script looks.
Human in the loop
A step only a person may decide: scope, taste, money or trust.
