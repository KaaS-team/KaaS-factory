Homework: kaas.team

kaas.team is a content factory with a small code surface

Most changes are books, newsletter issues and copy. The code that can hurt us is small: the lead form, the Plunk calls and the book bucket. So the factory here is mostly an editorial line with two human approvals, plus a short code line for lead and gate fixes.

1Team and codebase

Repository
Param-Harrison/kaas.team: Astro site, server.mjs and lead.mjs (Plunk lead capture), playbook books as web, PDF and EPUB in an R2 bucket, scenes in src/scenes/.
Where work comes from
Param's own list and the editorial desk. No GitHub issues yet, so nothing a factory could pick up today.
Team
One founder plus Claude Code sessions. Param reviews everything that ships.
Gates we already have
make check = build, node tests, a browser walk, Lighthouse (mobile performance, median of three, bar 95). A pre-push hook runs it and then checks every committed book matches the bucket copy. No CI: Coolify deploys on push to main.

7The factory for kaas.team

Isolation
Local runner, a worktree per issue. Plunk and R2 keys are not in the stage env, so a test cannot mail or publish.
Doer and Tester
Build writes the fix; verify reverts it and needs the named test red. Two rejects park the card.
Merge policy
Dry run. Every merge is Param's, because main deploys.
Circuit breaker
Two reverts of factory PRs in a week turn the route back to sessions only.
Demo card for the call
File the auto-subscribe bug as an issue against the commit before 0657164, run the factory, and show verify reverting the fix and the lead-kind test going red.
