Week 2, your blueprint. Questions 1 to 3 by Wed 28 Oct, 4 to 6 by Sat 31 Oct.

Decide what your agents know, may do and must prove

Your blueprint is the set of files in your repository that make every agent run the same way. Commit the files as you go. This sheet is the map of what you committed, so link to files where you can.

1What does every agent read first, and what only when needed?

The always-loaded file (CLAUDE.md or AGENTS.md) costs context on every task, so keep it short. Path rules, skills and subagents load only when they apply.

2What may an agent never touch, and what enforces it?

A rule that lives only in a prompt is a wish. Name what enforces each one: a permission deny, a blocking hook, code owners or branch protection.

3Which know-how will you turn into skills?

Anything you explain more than twice. Give each skill a name, say when to use it, and name the check it ends on.

4Which hooks run before and after the agent acts?

For example: block a protected path before a tool runs, format after an edit, run the gate when the agent says it is done. Say whether each one blocks or warns.

5What must every pull request prove before review?

List the gates with their commands, then the evidence a pull request must carry before a person reads it.

6Which review comment will you turn into a rule?

Read your last 20 review comments. A comment written three times becomes a rule, a skill, a lint or a test.
