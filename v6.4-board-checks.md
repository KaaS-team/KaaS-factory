## Issues

### #615 Readiness check: every open issue is a complete spec, and every epic lists real children

## Problem

Issues drift: a spec loses its Acceptance, carries a plan marker that skips the plan stage, or an epic names a child that is closed or missing. Nothing checks, so the board rots until a person audits it.

## Acceptance

- A check fails when an open non-ledger issue has no Problem, Acceptance or Out of scope section.
- It fails when an issue body carries the planned-plan marker or the `factory:planned` label without a hand-made plan.
- It fails when an epic lists a child that is closed or does not exist, and uses native sub-issues as the source of truth.
- It fails when an issue has no milestone, unless it is a ledger or labelled `later`.
- A fixture board has one passing and one failing case for each rule.
- The check runs in CI as report-only first, then required. The CI file is staged for a person to move.

## Out of scope

- Judging whether a spec is good.

### #165 Cut redundant checks and verification rounds from every run

## Problem

Some runs repeat checks and verification rounds that add cost without finding anything new. Parts are already shipped (model escalation, failure listing, selector-miss measurement). What is missing is a measurement of which checks ever catch something, so cuts are decided on data.

## Acceptance

- A report lists, per check and per round, how often it was the first to catch a real defect.
- Checks and rounds that never were are named with their cost.
- Any removal is its own issue, citing the report.

## Out of scope

- Removing a check in this issue.
