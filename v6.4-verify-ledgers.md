### #576 Harden the verify findings ledger against agent-written state

## Problem

`settleVerdict` in `src/engine/verdict-rules.ts` reads and writes `findings-ledger.json` and `prior-findings.json` inside the run directory of the worktree. An agent step has write access to that tree, so three weaknesses follow:

1. A symlink at either path makes the runner write through it to a file outside the run directory.
2. The ledger is trusted as written. A row marked resolved, or a ledger that omits a finding, lets a later round pass without resolving earlier rejects.
3. When a ledger exists, `prior` is not merged into it, so a finding listed in `prior-findings.json` but missing from the ledger is never counted as open. The ledger is also not rebuilt in `rehydrate()`.

## Fix

- Keep the ledger in runner state (as the receipt seal does), or rebuild it by replaying the verify markers in the issue thread through `mergeLedger`.
- If a file stays in the worktree: refuse anything that is not a regular file, remove the entry before writing, and write through a temp file plus rename.
- Always union `prior` into the ledger as open rows, and validate each row's schema on read.

## Acceptance

- A symlinked ledger or prior file is refused, with a test.
- A ledger edited to hide an open finding does not let a verdict pass, with a test.
- Each test fails with the fix reverted.

### #173 Let build and verify run read-only inspection commands, and count refused calls

## Problem

Build and verify agents may run only a short allow-list of read-only commands. A useful inspection command outside it (for example `git grep`) is refused, and the refusal is not counted, so nobody can tell how often agents are blocked or whether the list is too tight.

## Acceptance

- `git grep` is allowed in build and verify.
- Each refused tool call is counted, and the count is stored on the run.
- The stage guidance tells the agent which read-only commands it may use.
- A test proves a refused call is counted, and fails when the counter is removed.

## Out of scope

- Allowing any command that writes.

### #164 Failure ledger: every swarm failure, its fix, and proof the fix worked

## Problem

Every swarm failure should be recorded with its fix and proof that the fix worked. A ledger module exists on main (`src/failure-ledger.ts`, PR #494), but nothing writes to it from the runner, and this issue is a hand-kept table.

## Acceptance

- Each failed or parked run writes one row: cause, fix link, and the check that proves it.
- The hand-kept table is retired and the issue closed.
- A test proves a failed run produces a row, and fails when the write is removed.

## Out of scope

- Backfilling old failures.
