# CLI reference

Generated by `bun scripts/gen-cli-reference.ts --write` from `src/help.ts`. Do not edit by hand.

## Commands

### up

```
factory up [--repo-dir <path> | --repo <owner/name>] [--tmux]
```

no repo: control plane + relay (the image default); with a repo: watch + dashboard in one process; --tmux: each in a tmux window, plus one per issue.

### watch

```
factory watch (--repo-dir <path> | --repo <owner/name>) [--once]
```

poll and drive the loop; --once = one pass.

### run

```
factory run (--repo-dir <path> | --repo <owner/name>) (--issue <N> | --pr <N>)
```

advance one issue (or the issue a PR works on) once, then exit (CI).

### tick

```
factory tick (--repo-dir <path> | --repo <owner/name>)
```

one poll pass over every open issue, then exit (cron).

### park

```
factory park --repo-dir <path> (--issue <N> | --pr <N>) [--reason <text>]
```

park an issue as needs-human from outside the loop.

### daemon

```
factory daemon (install | uninstall) (--repo-dir <path> | --repo <owner/name>)
```

run `up` in the background at login, restarted when it exits (launchd on macOS, systemd user unit on Linux).

### dashboard

```
factory dashboard [--repo <owner/name> | --repo-dir <path>] [--port <n>]
```

serve the board (default :4100, loopback).

### attach

```
factory attach [<N>] (--repo <owner/name> | --repo-dir <path>) [--session <name>]
```

join the tmux session; with <N>, open that issue's live window (works over ssh -t and docker exec -it).

### takeover

```
factory takeover <N> (--repo-dir <path> | --repo <owner/name>) [--no-handback]
```

stop #N's running stage, open its Claude session in the worktree, and /factory retry when you exit.

### logs

```
factory logs <N> [--repo <owner/name>] [--stage <name>] [--follow] [--json]
```

print (or follow) a run's events; --json is one object per line.

### view

```
factory view <stream-file> [--follow]
```

render a stage's raw agent output in colour: tool calls, edit diffs, test results (the tmux issue window runs this).

### mcp

```
factory mcp (--repo <owner/name> | --repo-dir <path>) [--as <name>]
```

serve MCP on stdio, so an agent or IDE can list, read, start and approve tasks.

### runner

```
factory runner register --url <plane> [--name <n>] (token on stdin) | runner start --repo-dir <path>
```

register this machine with a control plane once, then dial out for work with heartbeats.

### pair

```
factory pair --url <plane> --login <member> (FACTORY_DASHBOARD_TOKEN set)
```

print a QR that pairs a phone to the plane as that member.

### inbox

```
factory inbox [<N> <action> [--text <words>]] (--repo <owner/name> | --repo-dir <path>) [--json]
```

list what waits for a human; with <N> <action>, post the same /factory comment a human would.

### scan

```
factory scan --repo-dir <path> [--lighthouse <report.json>]
```

file issues from `osv-scanner` (any lockfile), else `bun audit` on a Bun project; with --lighthouse, one per page below its bar.

### reset

```
factory reset --repo-dir <path> [--dry-run] [--all-issues]
```

DESTRUCTIVE: force base back to the baseline tag (lists dropped commits), close PRs and factory issues (--all-issues: every open issue).

### rebaseline

```
factory rebaseline --repo-dir <path> [--dry-run]
```

move the baseline tag to origin/<base>, keeping merged setup changes across reset.

### doctor

```
factory doctor --repo-dir <path> [--fix]
```

check the loop can run; --fix creates missing labels.

### explain

```
factory explain <N> (--repo-dir <path> | --repo <owner/name>)
```

print each config key for #N, its value and the level that set it (builtin, org, team or repo), the config hash and any team problems.

### verify-agent

```
factory verify-agent <name> --repo-dir <path> --issue <N> [--out <dir>]
```

run one issue on that agent, record a scrubbed fixture, print pass/fail, cost and tokens.

### learn

```
factory learn (--repo-dir <path> | --repo <owner/name>) [--export <file|-> [--since <date>]]
```

batch pending retro lessons and skill-edit proposals into one factory/learning-<date> PR; --export writes runs, stages and retros as v1 JSONL instead.

### init

```
factory init [--repo-dir <path>] [--dry-run] [--force] [--pr]
```

detect the repo's stack and write .factory/config.json gates, setup and commands; installs the template first if missing.

### harness

```
factory harness (validate | inventory | scaffold <name> | eval [--since <days>]) --repo-dir <path> [--json]
```

validate: every workflow file and every one the config names loads (exit 4 if not); inventory: each workflow's steps, cron triggers and routed types; scaffold: write a starting .factory/workflows/<name>.md; eval: runs, shipped rate, failed steps and cost per workflow from the event log.

### teach

```
factory teach "<how we ship>" (--repo-dir <path> | --repo <owner/name>) [--json]
```

one agent reads the repo, its CI and the brain MCP server, and opens a PR with the workflows, minions and skills it proposes, each checked first.

### minion

```
factory minion (list | run <name> [--event <json-file>]) --repo-dir <path> [--json]
```

list: every .factory/minions file, checked (exit 4 on a problem); run: one minion now, with an optional CloudEvent as its trigger.

### events

```
factory events (tail [--limit N] | replay <id>) --repo-dir <path> [--json]
```

tail: recent events in and out, with each sink's delivery status; replay: send one event to its sinks again.

### serve

```
factory serve [--port <n>] [--fixture two-repos] [--print-url]
```

serve the core API (routes, openapi.json, live events) on loopback, token-gated by FACTORY_API_TOKEN; --fixture serves seeded sample data.

### pool

```
factory pool [--json]
```

each pool runtime in machine.json: every member's free minutes used and left this month, and its last failure.

### runtime

```
factory runtime (list [--probe] | verify <name>) [--json]
```

list runtimes with their sandbox flags (--probe: does each answer); verify runs the shared conformance kit on one.

### dispatch

```
factory dispatch (--repo-dir <path> | --repo <owner/name>) [--json]
```

the issues one tick would advance, written to $GITHUB_OUTPUT as a matrix for one `factory run` job each.

### version

```
factory version (or --version)
```

print the runner version.

### routine

```
factory routine (--repo <owner/name> | --repo-dir <path>) [--cron <expr>] [--json]
```

print a Claude Code cloud routine (name, cron, prompt) that runs `factory tick` on a schedule.

### receipt

```
factory receipt (keygen --out <key.pem> | verify <receipt.dsse.json> --pubkey <key.pub>) [--json]
```

keygen: an Ed25519 key that signs each run's acceptance receipt; verify: check one here (kaas-verify checks it with no factory code).

### backup

```
factory backup (now | list | restore (--id <id> | --date <YYYY-MM-DD>) [--to <dir>] [--force]) [--json]
```

now: snapshot every state DB to the bucket with a sha256 manifest, then prune past FACTORY_BACKUP_KEEP_DAYS; list: the backups there; restore: check every sha256, then write the files (stop the stack first).

### install

```
factory install <target-dir> [--dry-run] [--update] [--ci] [--agents a,b,c]
```

install or update the template in a repo; --agents links skills into each agent dir.

## Options

- `--db <path>`: SQLite telemetry cache (default ~/.factory/state.db)
- `--workspaces <dir>`: worktree root (default ~/.factory/workspaces)
- `--json`: run, tick, watch --once, doctor and harness: print {ok,data} on stdout, and errors as {ok:false,error} on stderr
- `--tmux`: watch and up: show each issue's live transcript in a tmux window (config tmux.enabled does the same)
- `-h, --help`: print this help; after a command, that command's usage
- `--port <n>`: dashboard port (default FACTORY_DASHBOARD_PORT or 4100)

## Environment

- `FACTORY_HOME`: state root (clones, worktrees, db)
- `FACTORY_MODE`: set to `actions` when GitHub Actions drives the repo; doctor checks the workflow exists
- `FACTORY_DASHBOARD_HOST / _PORT / _TOKEN`: dashboard bind; a non-loopback host requires the token
- `FACTORY_DB_PATH / FACTORY_REPO`: dashboard-only defaults for --db / --repo
- `FACTORY_EVENTS_SECRET`: HMAC secret POST /events checks (config events.inboundSecretEnv names another); unset turns the route off
- `GH_TOKEN, ANTHROPIC_API_KEY`: credentials for VM/CI modes; the runner strips them from the agent env
