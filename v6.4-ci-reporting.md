## Issues

### #461 Show every CI failure in one run and name the failing test

## Problem

A CI run should show every failure at once and name the failing test. Part of this is on main (failure listing, PR #568). It is not confirmed that lint, typecheck and tests each report in the same run rather than stopping at the first red.

## Acceptance

- One red run lists lint, typecheck and test failures together, each with the failing test or file named.
- A run with one failure in each shows all three.
- If both cases already hold on main, this issue is closed with the evidence.

## Out of scope

- Hung tests: #478. Aborts with no named failure: #542.

### #478 CI test step needs a timeout that names the hung test

## Problem

A hung test makes the CI test step run until the job timeout (20 minutes on the push job) and then die with no indication of which test hung. Finding it means rerunning with logging.

## Acceptance

- A test that runs longer than a set limit is killed and named in the failure output, with how long it ran.
- The limit is one setting, not repeated per file.
- A test with a deliberate hang proves the name appears, and fails when the limit is removed.

## Out of scope

- Raising or lowering the job-level timeout.

### #542 A push check test step can abort with no failing test named

## Problem

A CI test step can abort with a non-zero exit while no failing test is named. The reader has only the exit code. A failure listing exists (PR #568), but it prints nothing in this case.

## Acceptance

- When the test step exits non-zero and no test failed, the output says so in one line and names the last test file that started.
- The cause found for the first case is written in the issue thread.
- A test covers the abort-with-no-failure case and fails when the line is removed.

## Out of scope

- Per-test timeouts: #478.

### #566 tests/git.test.ts fails under --rerun-each 3 on main

## Problem

`tests/git.test.ts` passes alone but fails on main under `--rerun-each 3`: some state is shared between repeats of the same test. The rerun check is how flaky tests are found, so a test that fails it hides real flakes.

## Acceptance

- `tests/git.test.ts` passes under `--rerun-each 3` ten times in a row.
- The shared state is named in the fix and removed, not retried around.
- A structural test fails if a test file leaves state that a second run of the same file depends on.

## Out of scope

- Other test files; each gets its own issue when found.

### #585 Run the gates test under rerun-each

## Problem

`tests/gates.test.ts` is not part of the rerun-each check, so a flaky test there goes unseen.

## Acceptance

- The file passes `--rerun-each 3` ten times in a row, or the shared state it keeps is removed.
- The rerun check includes it.

## Out of scope

- Other test files: #566.
