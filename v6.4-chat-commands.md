### #43 needs-human takes only retry and cancel: no way to send feedback back to build

## Problem

An issue parked as `needs-human` accepts only `/factory retry` and `/factory cancel`. When the reviewer wants to say what to change, there is no way to send that feedback back to the build step; they must edit the issue and retry blind.

## Acceptance

- `/factory revise <text>` on a `needs-human` issue resumes the run at the build step with the text available to the agent as feedback.
- A retry still resumes at the stage that last failed.
- A revise is applied once: it cannot replay after the run parks again with no new comment.
- Tests cover revise, retry and the replay case, and each fails when its behaviour is removed.

## Out of scope

- Revise on an in-review PR, which already exists.

### #73 A cancel comment replays after reopen, and a stale workspace skips worktree creation

## Problem

Two bugs in resuming a run:
1. A `/factory cancel` comment is read as the latest human comment with no check of when it was made. After the issue is reopened and relabelled, the old cancel is applied again and the run is cancelled a second time.
2. A workspace left over from an earlier run is not recreated when the run starts again, so the new run can start on a stale tree.

## Acceptance

- A chat command is applied once. After a reopen, a cancel older than the reopen is ignored.
- A stale or missing workspace is recreated before the run starts, and the run never starts on the old tree.
- Each bug has a test that fails when its fix is reverted.

## Out of scope

- Changing which commands exist.
