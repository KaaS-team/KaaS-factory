## Issues

### #621 Lease test depends on timing and fails under CI load

## Problem

`tests/lease.test.ts` "renews on the heartbeat while work runs, then releases" sleeps a fixed 40 ms and expects at least 3 heartbeats. It failed the CI gate on an unrelated PR and passed on rerun.

## Acceptance

- The test waits until it has seen the heartbeats, with a generous time limit, and uses no fixed sleep.
- It passes 20 runs in a row under `make test TEST_ARGS="--rerun-each 20"`.

## Out of scope

- Changing lease behaviour.

### #622 Run changed tests three times in the fast gate, and make the temp root survive a rerun

## Problem

CI runs new and changed tests three times, but `make fast` does not, so a test that breaks on its second run only fails after a push. `tests/preload.ts` removes its temp root after each run, which is what breaks them.

## Acceptance

- `make fast` runs new and changed tests three times, as CI does.
- `tests/preload.ts` leaves a temp root that a rerun can use, so tests need no `mkdirSync(tmpdir())` of their own.
- A test proves a rerun of a temp-dir test passes.

## Out of scope

- Other CI steps.

### #633 Fast gate runs generated-doc checks when their source changes

## Problem

A change to `src/help.ts` left `docs/cli-reference.md` stale, and `make fast` passed. Only the pre-push hook and CI caught it, after a full push cycle. Any generated file whose source changes should fail the fast gate, not the slow one.

## Acceptance

- `make fast` runs each generated-doc freshness check whose source files are in the change, starting with `make check-cli-reference` when `src/help.ts` or a file it imports changes.
- A test lists every generated file in the repo and fails when one has no freshness check wired into `make fast` through the impact map.
- A mutation that drops the cli-reference entry from the fast path makes that test fail.

## Out of scope

Regenerating docs automatically on commit.

### #634 Derive pinned line counts from the quality baseline

## Problem

Shrinking `src/cli.ts` by three lines needed a hand edit to a pinned count in a mutation file as well as to the baseline shard. The same number lives in two places, so every size change to a baselined file breaks an unrelated mutation.

## Acceptance

- The line-baseline mutation reads its expected count from the baseline shard instead of a hard-coded number.
- A test fails when any file under `tests/mutations/` pins a line count that also appears in a quality baseline shard.
- A mutation that restores a hard-coded count makes that test fail.

## Out of scope

Changing the line caps themselves.

### #635 Show drift between staged ci/ workflows and live ones

## Problem

Cloud runs cannot push to `.github/workflows`, so they stage workflow changes under `ci/`. The staged `ci/ci.yml` drifted from the live `.github/workflows/ci.yml` across several merges, and moving a staged file live risked undoing live changes. Nothing shows the drift.

## Acceptance

- A check compares each file under `ci/` with its live counterpart and prints the diff, so a lander moves only the staged change.
- `make check` fails when a staged file under `ci/` has no live counterpart and no note saying it is new.
- After a staged file is moved live, the check fails if the `ci/` copy is left behind.
- Each rule has a passing and a failing test, and a mutation that bites.

## Out of scope

Giving cloud runs permission to write workflows.

### #623 Check that vendored scripts/kaas files match the shared kit

## Problem

Files under `scripts/kaas/` are copied from a shared kit, and the next sync overwrites any local edit. An agent edited one in this repo, and only review caught it.

## Acceptance

- `make check` fails when a file under `scripts/kaas/` differs from the hash recorded at the last sync.
- The sync updates those hashes.
- A mutation proves the check bites.

## Out of scope

- Changing the kit.

### #624 Build agent briefs from the target repo's own toolchain

## Problem

Cloud agent briefs assume bun, `make fast` and `tests/mutations`. Sibling repos use npm or cargo, so agents there could not run the named steps, and a test landed that skips when playwright is absent.

## Acceptance

- The brief is built from the repo's own install, gate and mutation commands, read from its config.
- A repo with no gate config is refused before launch, with the reason.
- Launch refuses to start until the brief and any seed branch are confirmed on the remote.

## Out of scope

- New agent runtimes.
