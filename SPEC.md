## Risk: low

## Why
Parallel PRs conflict on append-only and generated files after every merge, and each conflict costs a model session. Most of these conflicts have a fixed answer: take main's file, or take main's file and regenerate it. A small deterministic resolver handles those with no model, and reports only the conflicts it cannot decide. Issue #384.

## Today
- Known conflict files: `quality-baseline.json` (generated by `bun scripts/gen-quality-baseline.ts`), `tests/mutation-list.test.ts` (take main's), `tests/mutations.json` (legacy list, take main's and keep this branch's additions as shards).

## Change
### T1: rule table and resolver
Files: `src/merge-resolve.ts`, `tests/merge-resolve.test.ts`
Model: sonnet
1. `src/merge-resolve.ts` exports `RULES`, a list of `{ match: (path: string) => boolean; action: "take-main" | "regenerate"; cmd?: string }`, with these entries: `quality-baseline.json` is `regenerate` with cmd `bun scripts/gen-quality-baseline.ts`; `tests/mutation-list.test.ts` and `tests/mutations.json` are `take-main`.
2. It exports `ruleFor(path)` returning the first matching rule or `undefined`.
3. It exports `resolveConflicts(repoDir, run = defaultRun)`, where `defaultRun` spawns a command in `repoDir`. It lists unmerged paths with `git diff --name-only --diff-filter=U`; for each path with a rule it takes main's side (`git checkout --ours`, because the worker merges the branch INTO a checkout of main; document that choice in a comment), then runs the rule's cmd if any, then `git add`. It returns `{ resolved: string[]; unresolved: string[] }` and never touches a path without a rule.
4. Tests, against a real temp git repo with a forced conflict: a conflicting `quality-baseline.json` is resolved to main's content and the cmd runs (inject `run` to record it); a conflicting `tests/mutation-list.test.ts` is resolved to main's content; a conflicting unlisted file such as `src/a.ts` stays in `unresolved` and its conflict markers are untouched.

### T2: worker CLI
Files: `scripts/merge-worker.ts`, `tests/merge-worker.test.ts`
Model: sonnet
Deps: T1
1. `scripts/merge-worker.ts <branch>`, run in a checkout: `git fetch origin main <branch>`, `git checkout -B work origin/main`, `git merge --no-ff --no-commit origin/<branch>`, then `resolveConflicts`. If `unresolved` is empty it commits with `-s` and prints `resolved N, ready`; otherwise it runs `git merge --abort`, prints each unresolved path, and exits 2. It never pushes; the caller pushes after the gate.
2. Test (temp repos, a bare "origin"): a branch whose only conflict is `quality-baseline.json` exits 0 and leaves a merge commit; a branch with a conflict in `src/a.ts` exits 2, names `src/a.ts`, and leaves the tree clean.

## Mutation
```json
{"name":"merge-resolve: take the branch side for baseline","file":"src/merge-resolve.ts","find":"checkout\", \"--ours\"","replace":"checkout\", \"--theirs\"","test":"tests/merge-resolve.test.ts"}
```
Adjust `find` to text that occurs exactly once in your file, and make sure the test goes red under it. Save it to `tests/mutations/merge-resolve-take-the-branch-side-for-baseline.json` (a single JSON object).

## Acceptance
- AC-1: a conflict in a listed file resolves to main's side and runs its regenerate command: checked by `make test FILES=tests/merge-resolve.test.ts` (T1)
- AC-2: a conflict in an unlisted file is reported, never guessed: checked by `make test FILES=tests/merge-resolve.test.ts` (T1)
- AC-3: the worker merges and commits when everything is resolved: checked by `make test FILES=tests/merge-worker.test.ts` (T2)
- AC-4: the worker aborts, names the file and exits 2 on an unresolved conflict: checked by `make test FILES=tests/merge-worker.test.ts` (T2)

## Non-goals
The worker does not push, open PRs or call a model; that stays with the caller. Do not wire it into `make check` or CI. Do not touch `.github/workflows`. No new dependencies. No em dashes, no filler words. Nothing outside Files.
