## Ticket: shadow mode (#611)

A dispatcher that runs nothing and records what it would have done, so a company can watch the factory on their repo before it touches anything.

Read first: `internal/dispatch/local` and `internal/dispatch/routines` for the Dispatcher shape, TS issue #611 text if available, `src/` grep for `shadow`.

Design to follow:
- `shadow.New(inner api.Dispatcher, w Writer) api.Dispatcher`: `Dispatch` records the brief, the dispatcher it would have used, and the session it would have created; it calls nothing on `inner` except `Name` and `Caps`.
- `Steer`, `Cancel` record and return nil. `Usage` returns zero.
- Records go to a `Writer` interface; the default writes one JSON line per action to `.factory/shadow.ndjson` (gitignored path; the file is never committed).
- A summary function reads the log and prints what would have run, per ticket, per day.

## Acceptance

- [ ] Wrapping a fake dispatcher, three Dispatch calls make zero calls to the inner Dispatch and three records.
- [ ] `Caps` and `Name` come from the inner dispatcher, `Name` prefixed `shadow:`.
- [ ] Summary of a fixture log groups by ticket and day (golden).
- [ ] The same brief twice gives the same would-be session id (idempotent like the real ones).
